# Версия для PHP-хостинга (SpaceWeb)

> Пошаговая инструкция «как залить» с проверкой каждого шага и разбором типичных ошибок —
> [UPLOAD-SPACEWEB.md](UPLOAD-SPACEWEB.md). Ниже — техническое описание для разработчика.

Сайт целиком на стандартном shared-хостинге: **PHP 8.x + Apache**, без Node.js, Composer
и MySQL. Расчёты выполняются в браузере, заявки реально сохраняются на сервере,
у кабинета специалиста — вход по паролю.

Инструкция проверена на SpaceWeb (виртуальный/бесплатный хостинг, тарифы с `public_html`).
Она же подходит для Beget, Timeweb, reg.ru и любого хостинга с PHP 8 + Apache.

## Сборка

```bash
npm run build:php
# для карты сайта и canonical подставьте свой адрес:
STATIC_SITE_URL=https://example.ru npm run build:php
```

Результат:

| Что | Где |
| --- | --- |
| каталог для заливки | `release/php/` |
| архив | `release/astra-pearl-php.zip` и копия в `download/astra-pearl-php.zip` |
| инструкция для владельца | `README.txt` внутри архива |

## Установка на SpaceWeb

1. **Панель → Файловый менеджер → `public_html`.**
   Удалите стандартные `index.html` и `.htaccess`, которые создаёт хостинг: иначе
   сайт покажет заглушку, а наш `.htaccess` не подхватится.
2. Загрузите архив `astra-pearl-php.zip` в `public_html` и распакуйте его там же —
   так, чтобы `index.html` оказался прямо в `public_html`.
   По FTP: путь тот же, `public_html`.
3. **Панель → Хостинг → Сайты → Конфигурация → «Настройки» → Версия PHP**: 8.0–8.5
   (по умолчанию хостинг может отдавать Apache 2.2 + PHP 7.1 — тогда сайт не запустится).
   Код прогнан на всех шести ветках (8.0, 8.1, 8.2, 8.3, 8.4, 8.5) — по 80 проверок на каждой.
   Нужны только расширения `json`, `session`, `hash`, `filter` — они есть в стандартной сборке.
   `mbstring`, `curl`, `openssl` не обязательны: без них код работает через встроенные замены.
4. **Права на запись.** Папка `data/` создана в архиве; PHP должен уметь в неё писать.
   Обычно достаточно 755, на некоторых тарифах — 775:
   Файловый менеджер → `data` → Права → 775 (или `chmod 775 data` по SSH).
5. **Установка.** Откройте `https://ваш-домен/setup.php`: кнопка «Создать config.php»
   создаёт файл настроек (в архиве его нет — так обновления не сбрасывают пароль),
   затем сразу смените пароль по умолчанию `astrolog` на свой (не короче 8 символов) —
   хеш запишется в `config.php` автоматически. Пока действует `astrolog`, страница
   `setup.php` открыта без токена и показывает предупреждение.
   После настройки **удалите** `setup.php`. Вход: `https://ваш-домен/cabinet/`,
   логин — `owner.login` (сейчас `Adelina`), можно ввести и `owner.email`.
6. **Домен и SSL.** Домен добавляется в панели SpaceWeb (на бесплатном тарифе —
   тестовый `*.swtest.ru`). Сертификат Let's Encrypt подключается там же, бесплатно.
   Редирект на https лежит в `.htaccess` **закомментированным**: раскомментируйте
   шесть строк после того, как сертификат станет активным, иначе сайт откроется
   с ошибкой сертификата. Пока сайт работает по http, кабинет показывает
   предупреждение о незашифрованном соединении.

## Настройки `config.php`

Файл лежит рядом с `index.html`, в git не попадает, из браузера закрыт (403).

| Ключ | Назначение |
| --- | --- |
| `siteName`, `siteUrl` | название и адрес сайта с https |
| `owner.login`, `owner.email`, `owner.passwordHash` | вход в кабинет: логин `Adelina` или почта; хеш выдаёт `setup.php`. Если `passwordHash` пуст, работает встроенный пароль `astrolog` (с напоминанием о смене) |
| `telegram.botToken`, `telegram.chatId` | уведомления о новых заявках в Telegram |
| `mail.adminEmail`, `mail.from` | письма через `mail()` хостинга |
| `security.salt` | соль для хеширования IP в лимитах (генерируется при сборке) |
| `security.setupToken` | доп. пароль для `setup.php` (генерируется при сборке) |
| `limits` | 5 заявок за 15 минут, 6 попыток входа, блокировка на 15 минут |
| `retentionDays` | срок хранения заявок, дни |
| `timezoneOffsetHours` | часовой пояс для времени в кабинете |

Telegram: создайте бота у `@BotFather`, отправьте боту `/start`, затем
`https://api.telegram.org/bot<токен>/getUpdates` — в ответе будет `chat_id`.

## Что именно работает

| Возможность | Как проверено |
| --- | --- |
| Натальная карта и Матрица судьбы | контрольные значения закреплены тестами (`tests/astronomy.test.ts`, `tests/matrix.test.ts`), сборка прогоняется в jsdom |
| Форма заявки шлёт POST на `api/lead.php` | jsdom-прогон собранного архива: проверены тело запроса, экран «Заявка принята» и номер заявки |
| Заявка сохраняется в `data/leads.php` | 80 проверок PHP-кода в php-wasm: запись, защита файла, лимиты, ошибки записи |
| Вход в кабинет, статусы, заметки, обезличивание | те же 80 проверок: сессия, CSRF, редиректы, 404, полный расчёт в карточке, вход при пустом `passwordHash` и без `config.php` |
| Совместимость с версиями PHP | 68/68 на PHP 8.0, 8.1, 8.2, 8.3, 8.4 и 8.5 (php-wasm) |
| Предупреждение о http | кабинет показывает плашку, если сайт открыт без шифрования |
| Правки в кабинете при ошибке записи | при недоступной `data/` API отдаёт 500 без номера заявки, кабинет показывает предупреждение и не пишет «сохранено» |
| Защита без `.htaccess` | `config.php` отдаёт пустой ответ и не раскрывает секреты, `inc/*.php` ничего не выводят |
| Проверка источника запроса и honeypot | 403 на чужой `Origin`, 422 на скрытое поле |
| Уведомления в Telegram | при пустых `botToken`/`chatId` канал честно помечается `skipped`; отправка проверяется только на реальном токене |
| Письма через `mail()` | в песочнице `mail()` недоступен, поэтому статус `failed` — это ожидаемо; на хостинге нужен ящик на вашем домене |

Что **не** заявляется как работающее: оплата онлайн, автоматические ответы клиенту,
двусторонняя переписка из кабинета. Кнопка «Повторное уведомление» отправляет
напоминание владельцу, а не письмо клиенту.

## Хранение данных и приватность

- Заявки и счётчики лимитов — файлы `data/leads.php` и `data/limits.php`.
  Первая строка каждого файла — `<?php exit; ?>`, поэтому прямое обращение из браузера
  отдаёт пустой ответ даже если `.htaccess` на хостинге отключён.
- IP-адреса не сохраняются: в лимитах лежит только `sha256(IP + salt)`, обрезанный до 24 символов.
- Обезличивание заявки в кабинете стирает имя, контакт и вопрос, оставляя историю статусов.
- Срок хранения задаётся `retentionDays`; удаляйте старые заявки вручную или по cron
  (`/usr/local/bin/php` на shared обычно доступен по SSH).

## Проверка после установки

1. Главная открывается с оформлением (шрифты `Cormorant Garamond` и `Manrope` локальные, без CDN).
2. Матрица на 23.06.1992 даёт центр 10 (Колесо Фортуны).
3. Натальная карта: Лондон, 01.01.2000, 12:00 — Солнце около 10° Козерога.
4. Тестовая заявка возвращает номер вида `AP-2026-001` и появляется в кабинете.
5. `https://ваш-домен/data/leads.php` отдаёт пустую страницу, `config.php` — 403.

## Частые сбои

| Симптом | Причина и что делать |
| --- | --- |
| Открывается заглушка хостинга | не удалён стандартный `index.html` или архив распакован во вложенную папку |
| 500 на `api/lead.php` | версия PHP ниже 8.0 либо нет прав на запись в `data/` (поставьте 775). Кабинет в этом случае показывает предупреждение, а API не выдаёт номер заявки |
| Заявка «ушла», но её нет в кабинете | кэш браузера или два разных `config.php`; проверьте, что архив распакован один раз |
| Письма не приходят | на shared `mail()` требует ящик на вашем домене — укажите его в `mail.from`; Telegram работает независимо |
| Не пускает в кабинет | логин — `owner.login` (`Adelina`) или `owner.email`; хеш из `setup.php` — одной строкой в одинарных кавычках |
| `.htaccess` вызывает 500 | хостинг на nginx без Apache: удалите `.htaccess`, защита данных всё равно работает через `<?php exit; ?>` в файлах |
| Сайт перекидывает на https с ошибкой сертификата | редирект включён до выпуска SSL | верните `#` в блоке `Rewrite` в `.htaccess` |

## Локальная проверка без хостинга

PHP в песочнице нет, поэтому серверная часть прогоняется в php-wasm
(сборка PHP 8.4 в WASM), а фронтенд — в jsdom на собранных архивах:

```bash
node tools/php-checks/api-cabinet.cjs                       # 80 проверок серверной части
PHP_VERSION=8.0 node tools/php-checks/api-cabinet.cjs        # то же на конкретной версии PHP (8.0–8.5)
npm run build:php && node tools/php-checks/form-api.cjs      # 31 проверка формы в режиме API
npm run build:static && node tools/php-checks/static-noserver.cjs   # 40 проверок без сервера
```

Подробности, установка php-wasm и список ограничений WASM-прогона —
[tools/php-checks/README.md](../tools/php-checks/README.md).
