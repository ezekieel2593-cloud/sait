# Заливка сайта на SpaceWeb — пошагово

Инструкция для владельца сайта: от «есть архив» до «заявка пришла в кабинет».
Всё делается в браузере, без программ и без командной строки. Время — 15–20 минут.

Если что-то пойдёт не так — в конце есть раздел [«Если не работает»](#если-не-работает)
с разбором конкретных симптомов.

---

## Что понадобится

| Что | Где взять |
| --- | --- |
| Логин и пароль от панели SpaceWeb | приходят на почту после регистрации, вход: `https://cp.sweb.ru` |
| Архив сайта `astra-pearl-php.zip` | файл в репозитории: папка `download/` → [прямая ссылка](https://raw.githubusercontent.com/ezekieel2593-cloud/sait/arena/58ef96c7-sait/download/astra-pearl-php.zip) |

> так и должно быть.
>
> Актуальная ссылка на архив лежит в репозитории: папка `download/` → `astra-pearl-php.zip`.

> `check.php` — страница самопроверки хостинга.

## Внимание: с чего начать, если вы скачали архив с GitHub

В репозитории лежит **исходный код проекта**, и он для хостинга не нужен. Если вы нажали
на GitHub «Code → Download ZIP» и распаковали его в `public_html`, вы увидите папки
`src`, `src-static`, `scripts`, `tests`, `tools` и файл `package.json` — это код для
разработчика, хостинг с ним сайт не покажет.

Для хостинга нужен **один файл внутри этого архива**:

```
скачанный-репозиторий/
└── download/
    └── astra-pearl-php.zip   ← ВОТ ЭТО и заливается на хостинг (≈0,8 МБ)
```

### Что делать, если исходники уже распакованы в `public_html`

1. В файловом менеджере откройте `public_html/ваша-папка-репозитория/download`
   и найдите файл **`astra-pearl-php.zip`** размером около **0,8 МБ**.
2. Скачайте его на компьютер: правый клик по файлу → **«Скачать»**
   (либо встаньте на файл → «Копировать», поднимитесь в `public_html` → «Вставить»).
3. Вернитесь в `public_html`, удалите папку с исходниками репозитория
   (`sait-arena-…` или `sait-main`) — на сайте она не нужна. Папку `cgi-bin` не трогайте.
4. Загрузите `astra-pearl-php.zip` в `public_html` → выделите → **«Распаковать»**
   в текущую папку → удалите сам zip.
5. Продолжите с [шага 6](#шаг-6-проверить-структуру-важнейший-шаг) — проверка структуры.

### В папке `download` один архив

| Файл | Размер | Для чего |
| --- | --- | --- |
| `astra-pearl-php.zip` | ≈0,8 МБ | сайт для PHP-хостинга (SpaceWeb): страницы, приём заявок, кабинет |

Других сборок в репозитории нет — версию без кабинета и серверную версию на Node.js
убрали, чтобы случайно не залить на хостинг не то. Они собираются из исходного кода
при необходимости (`npm run build:static`, `npm run package:release`) и в git не хранятся.

Признак правильного архива: в нём **нет** папок `src`, `tests`, `scripts` и файла
`package.json`, зато есть `index.html`, `api/`, `cabinet/`, `setup.php` и `check.php`
прямо в корне.

## Шаг 1. Войти в панель и найти свой сайт

1. Откройте `https://cp.sweb.ru`, войдите по логину и паролю из письма.
2. Слева (или сверху) откройте раздел **«Сайты»** / **«Мои сайты»**.
3. Найдите в списке свой домен. У бесплатного тарифа домен выглядит как `имя.swtest.ru` —
   именно его указывайте везде, где в инструкции написано «ваш-домен».
4. Запомните, что у сайта уже существует папка **`public_html`** — это и есть корень сайта,
   то, что видно в браузере по адресу домена.

## Шаг 2. Выпустить SSL-сертификат (сделать до загрузки)

Пока сертификата нет, сайт будет открываться только по `http`. Это безопасно для проверки,
но для формы заявки нужен `https` — иначе данные клиентов идут без шифрования.

1. В панели откройте **«SSL-сертификаты»** (может называться «Безопасность» → «SSL»).
2. Выберите свой домен → **«Выпустить сертификат»** → **Let's Encrypt** (бесплатный).
3. Дождитесь статуса «Активен» (обычно от минуты до часа — выпуск идёт автоматически).

Пока сертификат выпускается, спокойно переходите к шагам 3–7: они от него не зависят.

> В `.htaccess` сайта редирект на `https` **выключен по умолчанию** — специально, чтобы сайт
> открывался сразу после загрузки. Включим его в шаге 9, когда сертификат будет активен.

## Шаг 3. Проверить версию PHP в графе «Конфигурация»

По умолчанию хостинг может отдавать старую связку **«Apache 2.2 + PHP 7.1»** — сайт на ней
не запустится (нужен PHP 8.0+). Меняется это в том же разделе, где список сайтов.

1. Панель → **«Хостинг»** → **«Сайты»**.
2. Найдите свой сайт (`ezekieelya`) и посмотрите графу **«Конфигурация»**.

   - Написано **`Apache 2.4 + PHP 8.x`** — всё готово, переходите к шагу 4.
   - Написано **`Apache 2.2 + PHP 7.1`** (или другая 5.x/7.x) — нажмите ссылку
     **«Настройки»** под этой строкой:

3. В открывшейся странице найдите поле **«Версия PHP»** → выберите **8.3**
   (подойдёт любая с 8.0 по 8.5; на 8.5 сборка тоже прогнана) → **«Сохранить»**.
4. Подождите 1–2 минуты и обновите раздел «Сайты»: конфигурация должна стать
   `Apache 2.4 + PHP 8.3`. Вместе с PHP обновится и Apache 2.2 → 2.4 — `.htaccess`
   в архиве написан так, что работает на обеих версиях.

Больше в настройках PHP ничего менять не нужно: MySQL, Composer и установка библиотек
не требуются, хватает стандартных модулей `json`, `session`, `hash`, `filter`.

> Если после загрузки сайт вместо страниц отдаёт ошибку 500 — почти наверняка
> осталась версия PHP 7.x. Откройте `https://ваш-домен/check.php`: первая строка
> покажет фактическую версию и подскажет, что нажать.

## Шаг 4. Очистить `public_html`

Хостинг кладёт в эту папку свою заглушку — её нужно убрать, иначе вместо сайта
будет открываться «Добро пожаловать».

1. Панель → **«Файловый менеджер»** (прямая ссылка: `https://cp.sweb.ru/hosting/file_manager`).
2. Откройте папку **`public_html`**.
3. Удалите в ней:
   - файл **`index.html`** (страница-заглушка хостинга);
   - файл **`.htaccess`**, если он есть (конфиг хостинга; наш собственный приедет в архиве).
4. Папку `cgi-bin`, если она есть, **не трогайте** — она не мешает.

Если не видно `.htaccess`: в файловом менеджере включите показ скрытых файлов
(кнопка «Показать скрытые» / иконка глаза).

## Шаг 5. Загрузить архив

### Вариант А — через файловый менеджер (проще, рекомендую)

1. Останьтесь в папке `public_html`.
2. Нажмите **«Загрузить»** → выберите файл `astra-pearl-php.zip` с компьютера.
3. После загрузки выделите архив и нажмите иконку **«Распаковать»** (архив с молнией),
   распаковка — **в текущую папку**.
4. Удалите сам архив `astra-pearl-php.zip` из `public_html` — он больше не нужен.

Загружать именно архивом, а не россыпью файлов: внутри ~40 файлов и папок,
при ручной загрузке легко потерять скрытые файлы (`.htaccess`) или вложить всё лишний раз.

### Вариант Б — по FTP (если файловый менеджер тормозит)

1. В панели откройте раздел **«FTP»** / «FTP-доступы» и посмотрите **хост** (обычно
   `ftp.ваш-логин.sweb.ru`), логин и пароль. Точные значения показывает панель — берите оттуда.
2. Установите FileZilla, создайте подключение по этим данным, порт `21`.
3. Слева — папка с архивом на компьютере, справа — `public_html` на сервере.
   Перетащите архив вправо, дождитесь окончания передачи.
4. В панели (файловый менеджер) распакуйте архив — по FTP распаковать нельзя.
5. Удалите архив с сервера.

## Шаг 6. Проверить структуру (важнейший шаг)

В `public_html` должно лежать **вот это** (порядок в списке не важен):

```
public_html/
├── index.html          ← главная страница сайта
├── astrology.html
├── matrix.html
├── .htaccess           ← настройки Apache
├── config.example.php  ← образец настроек (config.php создаст setup.php)
├── config.js
├── setup.php           ← установка: создаёт config.php и задаёт пароль
├── api/                ← папка приёма заявок
├── cabinet/            ← папка кабинета
├── inc/                ← папка с кодом
├── data/               ← папка для заявок
├── fonts/
├── images/
└── ...
```

Типичная ошибка — папка внутри папки: `public_html/astra-pearl-php/index.html`.
Тогда сайт покажет ошибку или пустую страницу. Лечится так: выделите всё внутри
лишней папки → «Переместить» → в `public_html` → удалите опустевшую папку.

Проверьте в браузере: `http://ваш-домен/` — должна открыться главная страница со шрифтами
и меню. Если видите «Страница не найдена» от хостинга — вернитесь к шагу 4 и 6.

## Шаг 7. Дать PHP право писать в `data/`

Без этого заявки не сохраняются (сайт об этом честно предупредит в кабинете, но лучше сразу).

1. Файловый менеджер → `public_html` → правый клик по папке **`data`** → **«Права»**
   (или «Атрибуты», «chmod»).
2. Поставьте **775** (или `0755`, если 775 недоступно) → примените.
3. Убедитесь, что галочка «применить к вложенным» не нужна — внутри только `.htaccess`.

## Шаг 8. Установка: конфиг и пароль кабинета

Архив **не содержит** `config.php` — файл создаётся на хостинге, чтобы обновления
сайта никогда не сбрасывали ваши настройки. Поэтому установка — два действия в браузере.

1. Откройте `https://ваш-домен/setup.php` (если сертификат ещё не выпущен — `http://`, это разовая операция).
2. **Шаг 1 на странице — кнопка «Создать config.php».** Нажмите её. Файл появится сам,
   со случайными секретами (соль для лимитов и токен установки). Ничего копировать не нужно.
3. **Шаг 2 — сразу смените пароль.** Пока вы этого не сделали, в конфиге действует
   **пароль по умолчанию `astrolog`** — его знает любой, кто читал инструкцию. Страница
   `setup.php` в этом состоянии открыта без токена и показывает красное предупреждение.
   Введите свой пароль **не короче 8 символов** дважды и нажмите «Задать пароль».
   Хеш запишется в `config.php` автоматически — вручную ничего вставлять не надо.
4. Появится сообщение «Пароль сохранён в config.php», а предупреждение исчезнет.
   После этого `setup.php` без токена закрыт.
5. **Удалите `setup.php`** через файловый менеджер — он больше не нужен.
6. Войдите: `https://ваш-домен/cabinet/index.php` — или нажмите кнопку **«Войти»** в шапке
   сайта, рядом с «Рассчитать карту» (она видна на всех страницах и в мобильном меню).
   Логин — `Adelina`, пароль — тот, что задали на шаге 2.
   **Пока пароль не сменён, работает вход `Adelina` / `astrolog`** — даже если `config.php`
   ещё не создан или в нём пустое поле `passwordHash`. В кабинете при этом висит красное
   напоминание сменить пароль.

Если вместо кнопки появилось сообщение «Нет прав на запись в корень сайта» — хостинг
запретил PHP создавать файлы. Тогда: скачайте `config.example.php`, переименуйте в
`config.php`, загрузите в `public_html`, обновите страницу и задайте пароль.
Страница в этом случае покажет хеш для копирования в поле `'passwordHash'`.

### Как сменить пароль позже

Откройте `setup.php?token=…`, где токен — значение `security.setupToken` в `config.php`.
Без токена страница закрыта: посторонний не сможет сменить пароль, даже если
`setup.php` остался на хостинге.

## Шаг 9. Настроить уведомления в `config.php`

Откройте `config.php` в редакторе файлового менеджера. Правьте только значения
между кавычками, структуру и запятые не трогайте.

### Почта владельца и название сайта

```php
'siteName' => 'Название вашего сайта',
'siteUrl'  => 'https://ваш-домен',
'owner' => [
    'login' => 'Adelina',        // логин в кабинете; можно входить и по почте ниже
    'email' => 'вы@ваш-домен',
    // passwordHash уже записан автоматически в шаге 8 — не трогайте его
],
```

### Telegram — рабочий канал на любом тарифе

1. В Telegram найдите **@BotFather** → `/newbot` → придумайте имя и username.
   В ответ придёт **токен** вида `123456789:AAH...`.
2. Откройте своего бота (ссылка `t.me/ваш_бот`) и нажмите **«Запустить»** / отправьте `/start`.
   Без этого шага бот не сможет вам писать — самая частая причина «уведомления не приходят».
3. Узнайте `chat_id`: откройте в браузере
   `https://api.telegram.org/botТОКЕН/getUpdates`
   (вместо `ТОКЕН` — ваш токен). В ответе найдите `"chat":{"id":123456789,...}` — число и есть `chat_id`.
4. Впишите в `config.php`:

```php
'telegram' => [
    'botToken' => '123456789:AAH...',
    'chatId'   => '123456789',
],
```

### Почта для писем-дублей

```php
'mail' => [
    'adminEmail' => 'ящик@ваш-домен',  // куда присылать письма о заявках
    'from'       => 'ящик@ваш-домен',  // ящик, созданный в панели SpaceWeb
    'subjectPrefix' => 'Заявка с сайта',
],
```

Важно: на **бесплатном тарифе почтовых ящиков нет**, поэтому письма работать не будут —
это нормально, заявки всё равно сохраняются и приходят в Telegram. На платных тарифах
создайте ящик (Панель → «Почта») и укажите его в обоих полях.

Остальное можно не менять: срок хранения заявок (`retentionDays`, 365 дней),
часовой пояс кабинета (`timezoneOffsetHours`, 3 — Москва), лимиты антиспама.

## Шаг 9б. Название, подпись и всплывающее окно — `config.js`

Файл `config.js` лежит рядом с `index.html` и правится прямо в файловом менеджере.

```js
siteName: "Жемчужина",
logoText: "Жемчужина",
brandTitle: "Драгоценная жемчужина души",
brandTagline: "Драгоценная жемчужина души — ценность каждой женщины",
```

- `logoText` — короткое название в шапке (шрифт Cormorant, менять его не нужно);
- `brandTitle` — полное название: крупный заголовок на главной, строка под логотипом и подпись в подвале;
- `brandTagline` — короткая подпись-девиз в подвале.

### Манифест на главной

Под первым экраном — блок «Драгоценная жемчужина души». Текст берётся из `config.js`,
менять можно по абзацам, не трогая код:

```js
manifesto: {
  lead: "В каждой женщине живёт своя драгоценная жемчужина — её истинная суть…",
  paragraphs: [
    "Иногда она скрыта за страхами, сомнениями, чужими ожиданиями…",
    "Но однажды приходит время вернуться к себе…",
    "Этот путь — не о том, чтобы стать кем-то другим…",
  ],
  accent: "Ты не должна заслуживать свою ценность. Тебе предстоит её увидеть, принять и раскрыть.",
  closing: "Ведь каждая женщина — драгоценность, которой ещё предстоит узнать саму себя.",
},
```

### Вход по паролю по умолчанию

Логин `Adelina` и пароль `astrolog` работают **всегда**, пока в `config.php` не выключено:

```php
'security' => ['allowDefaultLogin' => true],
```

- `true` (по умолчанию) — подходят и ваши данные, и `Adelina` / `astrolog`;
- `false` — подходит только ваш пароль, заданный на `setup.php`.

Порядок для владельца: войти → `setup.php` → задать свой пароль (минимум 8 символов) →
поставить `'allowDefaultLogin' => false` → удалить `setup.php`. После этого вход только по вашему паролю.

Пароль по умолчанию в открытом виде в файлах не хранится — только его хеш.

### Полный доступ для владельца

Когда вы вошли в кабинет (`Adelina`), сайт под этим же браузером показывает
**полную расшифровку**: открыты все разделы матрицы и натальной карты,
закрытых карточек нет, форма заявки и всплывающее окно скрыты — себе заявку
отправлять незачем.

Гостям при этом показывается обычная версия с частью расшифровки: ограничения
снимаются только для владельца. Проверка идёт на сервере
(`api/session.php`), поэтому включить себе полный доступ из консоли браузера нельзя.

На странице результата владелец видит плашку «Вы вошли как владелец — показана
полная расшифровка». Сколько разделов открыто гостю, задаётся в `config.js`:

```js
freeResult: { astrologyCardCount: 4, matrixPointCount: 5 },
```

Чтобы увидеть версию глазами гостя — откройте сайт в режиме инкогнито
или нажмите «Выйти» в кабинете.

### Размер интерфейса

На компьютере сайт крупнее на четверть — так же, как при масштабе браузера 125%.
Всё построено на относительных единицах (`rem`), поэтому масштаб меняется одной строкой
в `styles.css`:

```css
@media (min-width:1024px){html{font-size:125%}}
```

- `125%` — как сейчас (крупно и читаемо);
- `100%` — как раньше, компактнее;
- `110%`, `115%` — промежуточные варианты.

На телефоне масштаб всегда 100%: там и так тесно. Меню и бургер переключаются
на 1344 px — при крупном интерфейсе шапке нужно больше места, иначе кнопки
упирались бы в край экрана.

### Фон сайта

Фон — жемчужная фотография в папке `images`:

- `images/pearl-background.jpg` — для компьютера (2560×1440);
- `images/pearl-background-mobile.jpg` — для телефона (1080×1600).

Чтобы поставить свою картинку, загрузите её в `images` **с тем же именем**.

**Важно про кэш браузера.** Сборка подставляет в адреса файлов отметку версии:

```
styles.css?v=fd42de06      app.js?v=fd42de06
config.js?v=fd42de06       images/pearl-background.jpg?v=cb45ef69
```

Благодаря ей после загрузки нового архива браузер сразу берёт свежие стили, скрипт и
фон — **Ctrl+F5 нажимать не нужно**. Если вы меняете картинку прямо на хостинге,
поправьте отметку в `config.js`, чтобы посетители увидели новую фотографию:

```js
assets: {
  background: "images/pearl-background.jpg?v=2",
  backgroundMobile: "images/pearl-background-mobile.jpg?v=2",
},
```

Фон прикрыт полупрозрачной вуалью только сверху и снизу, чтобы текст оставался
читаемым; фотография видна полностью.

### Всплывающее окно с вопросом и формой

Через 3 минуты после открытия страницы посетителю показывается окно: вопрос,
короткий текст и форма заявки. После закрытия оно возвращается ещё через 3 минуты —
то есть показывается **каждые 3 минуты нахождения на сайте**. Закрывается крестиком,
клавишей Esc или кликом по фону. После отправки заявки из окна оно больше не появляется.

```js
invite: {
  enabled: true,      // false — окно не показывать совсем
  delayMs: 180000,    // интервал в миллисекундах (180000 = 3 минуты)
},
```

Если человек в этот момент печатает в форме, окно подождёт и появится позже.
На страницах «Политика конфиденциальности» и «Условия» окно не показывается.

## Шаг 10. Включить редирект на HTTPS

Делайте это **только после** того, как сертификат из шага 2 стал активным
(сайт открывается по `https://` без предупреждений браузера).

1. Откройте `.htaccess` в файловом менеджере (редактор).
2. Найдите закомментированный блок:

   ```
   # <IfModule mod_rewrite.c>
   #   RewriteEngine On
   #   RewriteCond %{HTTPS} !=on
   #   RewriteCond %{HTTP:X-Forwarded-Proto} !https
   #   RewriteRule ^(.*)$ https://%{HTTP_HOST}/$1 [R=301,L]
   # </IfModule>
   ```

3. Уберите `# ` в начале этих шести строк (включая `# <IfModule...>` и `# </IfModule>`).
4. Сохраните и откройте сайт по `http://` — он должен сам перекинуть на `https://`.

Если после правки сайт выдал ошибку 500 — значит строка вставлена с опечаткой:
верните `#` обратно, сохранитесь, и напишите нам — включим иначе.

## Как обновлять сайт

В архиве нет `config.php`, а папка `data/` не перезаписывается. Значит, обновление
больше не может сбросить пароль или потерять заявки — но копию всё же полезно иметь.

1. Скачайте новый `astra-pearl-php.zip`.
2. Откройте `public_html`, загрузите архив, выделите его → **«Распаковать»** →
   в текущую папку. На вопрос о существующих файлах ответьте «заменить/перезаписать».
3. Удалите архив.
4. Откройте `https://ваш-домен/check.php` — все строки должны быть «ок».
5. Проверьте вход в кабинет (пароль сохраняется) и одну тестовую заявку.

### Что стоит сохранить у себя

| Что | Зачем | Как |
| --- | --- | --- |
| `config.php` | там хеш пароля, токен Telegram и почта владельца | правый клик → «Скачать» |
| `data/` | заявки клиентов | правый клик → «Архивировать» → скачать `data.zip` |

Держите копию вне хостинга: если вы случайно удалите `config.php`, вход в кабинет
перестанет работать, а настройки придётся вводить заново. Восстановление: загрузить
файл обратно в `public_html` с заменой.

## Что важно знать про безопасность

- `config.php` хранит пароль-хеш и токен бота. Он закрыт от браузера через `.htaccess`
  и, даже если хостинг отключит `.htaccess`, отдаёт пустой ответ — это проверено тестами.
- `data/` с заявками закрыт так же; файлы начинаются со строки `<?php exit; ?>`.
- По прямому адресу `data/leads.php` должна открываться пустая страница. Если вы увидели
  JSON с именами клиентов — сообщите немедленно: значит, хостинг настроен нестандартно.
- IP-адреса клиентов не хранятся: в лимитах лежит только необратимый хеш.
- Никогда не выкладывайте `config.php` в открытые репозитории и не пересылайте его в чатах.
