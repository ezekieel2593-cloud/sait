# Интеграции уведомлений

Уведомления о заявках отправляются **после** сохранения заявки в базе. Каждая попытка
пишется в журнал `notifications` со статусом:

| Статус | Значение |
| --- | --- |
| `pending` | попытка создана, отправка ещё не завершилась |
| `sent` | провайдер подтвердил доставку (HTTP 2xx / принято SMTP) |
| `failed` | провайдер вернул ошибку; текст ошибки сохранён в `last_error` |
| `skipped` | канал не настроен, отправка не выполнялась |

Отправить повторно можно в карточке заявки («Отправить уведомления повторно») — в журнал
добавляется событие `notifications_retry`. Состояние каналов видно в кабинете:
`/specialist/settings` → «Интеграции».

Секреты хранятся только в переменных окружения сервера. В базе и в интерфейсе их нет.

## Telegram (Bot API)

1. Создайте бота у [@BotFather](https://t.me/BotFather), получите токен.
2. Напишите боту любое сообщение (или добавьте в нужную группу).
3. Узнайте `chat_id`: вызовите `https://api.telegram.org/bot<TOKEN>/getUpdates` и возьмите
   `message.chat.id` (в группах значение отрицательное).
4. Заполните переменные:

```env
TELEGRAM_BOT_TOKEN=123456:AA...
TELEGRAM_CHAT_ID=123456789
```

**Проверка:** отправьте тестовую заявку на сайте и убедитесь, что в кабинете в карточке заявки
статус канала стал `sent`. Если `failed` — текст ошибки указан рядом.

Метод: `POST https://api.telegram.org/bot<token>/sendMessage` с `chat_id` и `text`.

## MAX (platform-api.max.ru)

Важно: по правилам платформы ботов в MAX с сентября 2025 могут создавать только
**верифицированные юридические лица РФ** после модерации. Если у вас нет такого аккаунта,
канал физически недоступен — интеграция не имитируется: в кабинете он будет показан как
«не настроено», а заявки сохраняются и приходят другими каналами.

1. Получите токен бота в кабинете MAX для бизнеса.
2. Узнайте `chat_id` диалога с ботом (или канала).
3. Заполните переменные:

```env
MAX_BOT_TOKEN=...
MAX_CHAT_ID=...
MAX_API_BASE=https://platform-api.max.ru
```

**Проверка:** `curl -H "Authorization: $MAX_BOT_TOKEN" https://platform-api.max.ru/me`
должен вернуть данные бота. Токен передаётся **только** заголовком `Authorization`,
в query-параметрах он не используется.

Метод отправки: `POST {MAX_API_BASE}/messages?chat_id=<chat_id>` с JSON `{ "text": "..." }`
и заголовком `Authorization: <token>`.

## E-mail (SMTP)

Подходит любой SMTP-провайдер (свой сервер, транзакционный сервис, корпоративная почта).

```env
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_SECURE=false
SMTP_USER=robot@example.com
SMTP_PASSWORD=...
MAIL_FROM="Astra Pearl <robot@example.com>"
```

Получатель письма — «Email для уведомлений» в настройках кабинета (`contacts` → adminEmail,
по умолчанию `MAIL_ADMIN`).

**Проверка:** попросите владельца почтового ящика проверить папку «Спам» после тестовой
заявки. Для порта 465 используйте `SMTP_SECURE=true`.

Внимание: `nodemailer` отправляет письмо только после реального ответа SMTP-сервера;
статус `sent` означает, что сервер принял письмо, а не что оно прочитано.

## Геокодер (необязательно)

По умолчанию поиск города работает по локальному справочнику (`src/lib/astronomy/cities.ts`)
и не требует сети. Внешний геокодер можно включить переменными `GEOCODER_PROVIDER` и
`GEOCODER_USER_AGENT`; без него сервис полностью работоспособен.

---

## Чего сервис не делает

- Не отправляет SMS и сообщения в мессенджеры без настроенного канала.
- Не помечает отправку успешной, если провайдер вернул ошибку — статус остаётся `failed`
  с текстом ошибки.
- Не хранит токены в базе, в репозитории или в логах.
