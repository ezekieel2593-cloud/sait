# Проверки версии для PHP-хостинга

PHP в этой песочнице нет (пакеты ставить нельзя), поэтому серверная часть
прогоняется в **php-wasm** — сборка PHP 8.4 в WebAssembly. Настоящий Apache и
сеть при этом не участвуют: проверяются сами файлы `php/`, их логика и ответы.

## Установка php-wasm (один раз)

```bash
mkdir -p /tmp/phptest && cd /tmp/phptest
npm init -y >/dev/null && npm i php-wasm     # ≈90 МБ, в репозиторий не попадает
```

## Запуск проверок

```bash
# 1. Серверная часть: API заявок, лимиты, кабинет, setup.php (94 проверки)
node tools/php-checks/api-cabinet.cjs

# на конкретной версии PHP (php-wasm ставит 8.0, 8.1, 8.2, 8.3, 8.4, 8.5):
PHP_VERSION=8.0 node tools/php-checks/api-cabinet.cjs

# 2. Форма в собранном PHP-пакете (35 проверок, jsdom)
npm run build:php && node tools/php-checks/form-api.cjs

# 3. Установка: config.php, пароль, вход Adelina / astrolog (24 проверки)
node tools/php-checks/setup-flow.cjs

# 4. Диагностическая страница check.php (18 проверок)
node tools/php-checks/check-page.cjs

# 5. Статическая версия без сервера (58 проверок, jsdom)
npm run build:static && node tools/php-checks/static-noserver.cjs
```

Если php-wasm установлен в другую папку:

```bash
PHP_WASM_DIR=/путь/к/папке node tools/php-checks/api-cabinet.cjs
```

Код возврата `0` — все проверки прошли, `1` — есть падения.
Полный прогон по версиям:

```bash
for v in 8.0 8.1 8.2 8.3 8.4 8.5; do PHP_VERSION=$v node tools/php-checks/api-cabinet.cjs | tail -1; done
```

## Что именно проверяется

`api-cabinet.cjs`:

| Блок | Проверки |
| --- | --- |
| Заявка | запись в `data/leads.php`, номер `AP-YYYY-NNN`, защита файла, отсутствие сырого IP |
| Валидация | 422 на плохой контакт и пустое имя, honeypot, 403 на чужой `Origin`, 405 на GET |
| Лимиты | 3 заявки проходят, четвёртая — 429 |
| Вход | форма, неверный пароль, 303 + cookie `Secure/HttpOnly/SameSite`, noindex/no-store |
| Кабинет | список, карточка, CSRF, смена статуса с комментарием, заметки, 404, фильтры |
| Обезличивание | удаление имени и контакта, сохранение истории |
| setup.php | закрыт при заданном пароле, открыт с токеном, отказ на короткий пароль |
| Защита | `<?php exit; ?>` в файлах данных, хеши IP в лимитах |
| Без `.htaccess` | `config.php` не отдаёт секретов, `inc/*.php` молчат, GET на API — 405 |
| Ошибки записи | при недоступной `data/` API отдаёт 500 без номера, кабинет предупреждает, после починки прав заявки снова сохраняются |
| HTTPS | по http кабинет показывает предупреждение о незашифрованном соединении |
| Установка | setup.php создаёт config.php со случайными солью и токеном, записывает хеш пароля (не через preg_replace с «$2»), закрывается после настройки, проверяет совпадение паролей |

Ограничения WASM-прогона (поэтому часть статусов проверяется иначе):

- встроенный SAPI не переживает `exit`, поэтому в проверках определяется
  константа `APP_TEST_NO_EXIT` и `app_exit()` бросает исключение вместо выхода;
- `php://input` недоступен — тело запроса передаётся через `$GLOBALS['APP_TEST_INPUT']`;
- данные сессии между запусками не сохраняются, поэтому сессия владельца
  для проверок кабинета заполняется заранее известными значениями;
- `mail()` в WASM отсутствует → статус письма `failed` — ожидаемое поведение;
- сети нет → Telegram-канал при пустых настройках помечается `skipped`.

Реальную отправку в Telegram и работу `mail()` на хостинге эти проверки
не подтверждают: их нужно проверить один раз на живом домене с настоящим токеном.
